## 실제 DB 대조를 위해 사용자가 할 최소 작업

1. 제공한 실행 도구 ZIP을 압축 해제하고 `READ_DB_ONLY.cmd`를 실행한다. Python 3이 필요하며, PostgreSQL 드라이버가 없으면 자동으로 설치한다.
2. Railway에서 **PostgreSQL 서비스 → Variables → `DATABASE_PUBLIC_URL` 값**을 복사해 프로그램의 숨김 입력란에 붙여넣고 Enter를 누른다. 앱 서비스의 `postgres.railway.internal` 주소는 PC에서 연결되지 않는다. URL·비밀번호를 채팅에 보내지 않는다.
3. 생성된 **`railway_readonly_snapshot.json` 파일 하나만 전달**한다. 접속 URL이나 비밀번호는 출력 파일에 저장되지 않는다.

외부 접속 URL이 이미 제공돼 있을 때의 방법이다. 해당 값이 없다면 임의로 공개 네트워크/운영 설정을 변경하지 말고, 기존 Railway CLI 연결이 있다면 `railway connect --tunnel-only`의 읽기 전용 접속 경로를 사용할 수 있다. 프로젝트·환경·PostgreSQL 서비스 선택이 필요하며, DB 접속 자체는 데이터를 변경하지 않는다.

공식 근거: [Railway PostgreSQL](https://docs.railway.com/databases/postgresql), [railway connect](https://docs.railway.com/cli/connect).

### 내보내기 프로그램의 동작

- 앱·마이그레이션 모듈을 불러오지 않는다. 회원/변경이력/운영 설정을 쓰지 않는다.
- 접속 시 `default_transaction_read_only=on`, 이후 `REPEATABLE READ + READ ONLY`로 고정하고 실제 읽기전용 상태를 확인한다. 종료 시 rollback한다.
- SELECT/SHOW/트랜잭션 설정만 사용한다. 60초 쿼리 제한과 5초 락 대기 제한을 둔다.
- 변경이력 원본/ID와 판정, 필요한 주소 열, 회원 최소 필드, 폐업대장, 관련 수정 이력, 변경이력 연동 월례보고 수기값만 내보낸다. 주민번호·계좌·비밀번호·토큰 관련 필드는 제외한다.
- 원본에 DB ID가 없으므로 최초 연결은 업무 원본 9개 항목의 **양쪽 유일 일치**로 수행한 뒤 DB ID를 기준으로 결과를 관리한다. 다대일/일대다/삭제 기록은 임의 ID를 부여하지 않는다.
- 정확 일치가 없을 때는 알려진 유형 별칭(`차량번호변경/번호변경` 등), 같은 유효 날짜의 표기, 차량번호 공백·끝의 `호`만 정규화한 양쪽 유일 일치를 별도로 인정한다. 사용한 정규화와 실제 DB 원본 지문을 기록한다. 주소·상호·메모·변경 전후 값은 수정하지 않으며 이름 유사도 같은 추측 연결은 하지 않는다.

```bash

```

결과는 `reconciliation.csv`(DB ID 연결), `db_monthly.csv`(전체 실제 스냅샷 기준 전후 예상), `saved_report_comparison.csv`(기존 수기값과 표시값 차이), `existing_decision_conflicts.csv`(기존 명시 판정), `unmatched_db.csv`(추가 DB 기록)다. 스냅샷에 없는 값을 0건으로 채우지 않는다.

기존 main의 구조변경→대폐차 합산 및 등록이관→이전전출 합산을 별도로 재현한다. '코드만 변경'과 '사용자 지정 제외 판정까지 반영한 후보'를 구분한다. 고정 제외 13건과 지정 중복 보류 2건을 DB ID에 연결·저장하지 않은 채 운영에 배포하면 안 된다.

현재 제공된 월례보고 표는 원본 미리보기다. 운영 DB 자료를 받지 않았으므로 실제 운영 대조 결과는 미수신으로 표시했다. 비교표의 값은 반영 전 예상이며, 어떤 DB도 수정하지 않는다. 일부 항목은 포함관계가 있으므로 행을 단순 합산하지 말고 `_변경등록전체`를 사용한다.

## GitHub Push 차단 시 최소 대안

