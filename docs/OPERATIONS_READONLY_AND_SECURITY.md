# 조회 읽기 전용 · 직원/관리자 권한 · SECRET_KEY 점검 안내

## 1. 조회(GET)는 DB를 바꾸지 않습니다
- 회원 상세 조회가 하던 일(프로필 자동 생성, 기준잔액·계정을 예전 기준자료 값으로 덮어쓰기, 자동부과 삭제·재생성)을 제거했습니다.
- 프로필이 없는 회원은 상세 조회 시 404 + 안내 문구가 나옵니다. 프로필은 **관리자 '원장 동기화'** 또는 수납 입력 시 생성됩니다.
- 모든 `/api/receivables` GET 요청을 실행하면서 INSERT/UPDATE/DELETE 가 한 번이라도 나가면 실패하는 자동 테스트를 추가했습니다.

## 2. 백그라운드 동기화는 기본 꺼짐 → 관리자 명시적 실행
- 이전: 서버 시작 90초 후부터 15분마다 프로필 생성·월 부과·전체 대조가 자동 실행.
- 이후: 기본 꺼짐. 환경변수 `RECEIVABLES_BACKGROUND_SYNC=1` 로만 켤 수 있음.
- **월 부과(매월 1일 이후)와 신규 회원 프로필은 관리자가 '회원/부과 동기화' 버튼(관리자만 표시)을 눌러야 생성됩니다.** 누르기 전에 현황은 `GET /api/receivables/admin/sync-status`(읽기 전용)로 확인됩니다.
- 동기화는 과거 부과를 삭제하지 않습니다(무효 부과는 잔액 계산에서만 제외).
- 예전처럼 자동으로 돌리고 싶으면 Railway 변수에 `RECEIVABLES_BACKGROUND_SYNC=1` 추가 후 재배포(이 경우 조회와 무관하게 주기적으로 DB가 갱신됨).

## 3. 권한 (일반 직원 / 관리자)
| 구분 | 일반 직원(staff) | 관리자(admin) |
|---|---|---|
| 수납 입력·수납 취소·연락기록·계정 설정·통장 업로드(미리보기/회원 연결/수납 반영) | 가능 | 가능 |
| 금액수정, 미수금 정정(미리보기 확인 후 적용), 정정 되돌리기, reconcile, 원장 동기화, 점검 화면 | **불가(403)** | 가능 |
- 수납 입력으로 `잔액수정`(금액수정 우회)을 넣는 것은 막혀 있습니다(실제 입금만 입력).
- **새로 추가되는 변경 API는 기본이 관리자 전용**입니다. 직원에게 열려면 코드에 `@staff_write_ok` 표시가 필요하며, 허용 목록은 테스트로 고정되어 있습니다.

## 4. SECRET_KEY
- 코드에 기본 비밀키가 없습니다(예전 기본값 문자열이 환경변수로 들어와도 '미설정'으로 취급).
- Railway(운영)에서 SECRET_KEY 가 없거나 예전 기본값이면 **서버가 시작을 거부**합니다(배포 실패 → 이전 정상 배포 유지). 32자 미만이면 시작은 되지만 경고합니다.
- 개발/테스트에서는 프로세스마다 무작위 임시 키를 만듭니다.

### Railway 에서 값을 노출하지 않고 점검하는 방법
1. **대시보드**: 프로젝트 → `production` → `회원 관리` 서비스 → **변수(Variables)** 탭에서 `SECRET_KEY` 항목이 있는지만 확인합니다(값은 가려져 있으며 눈 아이콘을 누르지 마세요).
2. **CLI(값 비노출)**: `railway variables --kv | cut -d= -f1 | grep -x SECRET_KEY` → `SECRET_KEY` 한 줄이 나오면 설정됨(`cut` 으로 이름만 남기므로 값은 출력되지 않음).
3. **점검 도구**: `railway run python -m scripts.check_secret_key` → 설정 여부·길이 구간·기본값 여부만 JSON 으로 출력(종료코드 0 정상 / 1 경고 / 2 시작 거부 상태).
4. **관리자 API**: 관리자 로그인 토큰으로 `GET /api/admin/security-status` → `secret_key_configured`, `secret_key_length_ok` 등 불리언만 반환.
5. 배포 로그에 `SECRET_KEY 환경변수가 설정되지 않았습니다` 가 보이면 설정이 빠진 것입니다.
- 키를 교체하면 모든 사용자가 다시 로그인해야 합니다. 이전 노출(과거 `.env` 커밋)을 고려하면 교체를 권장합니다.
