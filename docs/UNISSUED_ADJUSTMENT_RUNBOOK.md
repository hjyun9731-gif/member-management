# 자격증명 미발급 회원 관리비 미수금 정정 — 배포·실행 안내서

## 무엇이 바뀌었나
- **판정**: `certificate_issue_date`와 `certificate_number`가 **둘 다 비어 있을 때만** 미발급. 하나라도 있으면 미발급이 아님(예: 발급번호만 있는 송제욱).
- **자동정정 대상은 '택배(차량번호에 배) 미발급 + 관리비 계정 + 양수 미수'만**. 아래는 자동정정하지 않고 **별도 검토 목록**으로 분리됨:
  비택배(배 번호판 아님) / 폐업 회원 / 계정 불일치(회원정보상 협회 가입자인데 관리비 프로필). 선납(음수)·0원은 그대로 둠.
- **정정 전용 테이블** `receivable_adjustments`(+`receivable_adjustment_batches`): 회원ID·계정·정정 전/후 잔액·정정액·사유·작업자·일시·배치ID 기록. **실제 수납(`receivable_payments`)에는 아무것도 넣지 않음** → 수납 통계·통장 입금액·월별 수납액에 들어가지 않고, 월별 장부에서는 "잔액 조정"으로만 표시.
- **단일 잔액식**: `기준잔액 + 유효 부과 − 실제 수납 − 정정`. 회원 상세/금액수정/일괄정정은 `_canonical_balance_parts`, 목록·대시보드·통계·엑셀·지로 목록은 같은 규칙의 SQL(`_balance_sql_core`)을 사용. 둘의 일치는 `/api/receivables/adjustments/consistency`로 검증.
  - 목록/통계 SQL이 상세화면과 달랐던 원인: 상세만 "미발급 회원의 자동부과 등 무효 부과"를 걸러냈음(김종진 215,000 vs 210,000의 5,000원). 이제 목록도 같은 부과 규칙을 적용(**부과 내역은 삭제하지 않고 잔액 계산에서만 제외**).
- 신규 관리비 자동부과 차단은 기존 `_auto_charge_allowed_for_month`(미발급이면 연도 무관 차단) 유지. 서버 시작 시 정정은 **실행되지 않음**(테스트로 보장).
- 회원 연결은 **회원 ID로만**(이름·차량번호 매칭 없음).
- **금액수정(수동 1건)도 가짜 수납을 만들지 않음**: `receivable_adjustments`에 기록(관리자 전용). 수납액·통계에 안 들어가며 회원 상세에 "정정 내역(실제 입금 아님)"으로 별도 표시, 배치 되돌리기 가능.
- **변경 API 관리자 필수**: 수납·미수금 모듈의 POST/PUT/PATCH/DELETE 와 `GET /api/receivables/sync`(데이터를 만드는 GET)는 로그인+관리자만 가능(라우터 단위 `admin_for_writes`). 이전에 인증이 없던 `reconcile-20260916-v4` status/apply 도 포함. 
  **주의: 일반 직원(staff) 계정은 이제 수납 입력·연락기록·통장 업로드 반영 등도 할 수 없음.** 직원이 입력해야 한다면 해당 계정을 관리자로 두거나 `admin_for_writes` 적용 범위를 조정해야 함.
- 월별 장부(월별 원장)도 같은 규칙(무효 자동부과 제외 + 정정 반영)을 사용.
- 자격증명 발급비·대폐차 수수료는 이 원장에 미수금으로 저장되지 않으며 정정 대상이 아님(관리비 계정 월부과 잔액만 정정).

## 배포 순서 (운영 DB는 정정을 누르기 전까지 변하지 않음)
1. **백업**: Railway → Postgres 서비스 → Backups 에서 백업 생성, 복구 가능 여부 확인(테스트 DB로 복원해 보기 권장).
2. 이 브랜치(`fix/receivables-adjustments`)를 테스트 환경(Railway에서 별도 환경/서비스)에 배포해 확인. 새 테이블 2개는 시작 시 자동 생성(기존 테이블 변경 없음).
3. 승인 후 `main`에 병합 → 자동배포. 배포만으로는 데이터가 바뀌지 않음.

## 안전한 일괄 정정 실행 (관리자, 1회)
1. 통합 원장(`/receivables/workspace`) → **미수금 정정(관리자)** 탭.
2. **미리보기**(DB 변경 없음) 확인 → "회원별 보고서 CSV"에서 이름·차량번호·발급일자/번호·기존 미수금·정정 예정액 검토. 비택배/법인 표시, 제외 사유 확인.
   - 특정 회원을 빼려면 API `preview?exclude=ID,ID` 사용(digest가 달라짐).
3. 백업 확인 체크 + 확인 문구 `ZERO_UNISSUED_MANAGEMENT` 입력 → **정정 적용**.
   - 미리보기 이후 자료가 바뀌면(입금 등) 거부됨 → 미리보기를 다시 확인.
   - 한 번 적용되면 재실행 거부(유효 배치 1개, 회원별 부분 유니크 인덱스). 오류 시 전체 롤백.
4. **적용 후 검증** 버튼: 대상 잔액 0원, 실제 수납·부과 합계 불변, 화면 계산 불일치 0 확인.
5. 문제가 있으면 **되돌리기**(VOID_ADJUSTMENT_BATCH): 정정을 무효 처리(기록은 삭제하지 않음).
- 명령줄: `python -m scripts.zero_unissued_management_arrears [--csv out.csv]`(미리보기) / `--apply --plan-digest <값> --confirm ZERO_UNISSUED_MANAGEMENT --backup-confirmed`(적용).

## 알려진 한계
- 운영 DB 실제 수치(276명/36명/7,925,000원)는 이 환경에서 재현 불가 — 운영에서 미리보기로 새 기준 수치를 확정해야 함.
- 폐업 회원의 기준잔액(폐업월 기준 재구성)은 SQL 목록이 단순 기준잔액을 쓰는 기존 차이가 남아 있을 수 있음 → consistency 보고서에서 확인.
- 지로 희망 표시는 기존처럼 이름+차량번호 매칭(표시 전용, 정정과 무관).
- 기존 "금액수정" 기능은 여전히 `잔액수정` 수납 행을 만든다(이번 범위 밖).
